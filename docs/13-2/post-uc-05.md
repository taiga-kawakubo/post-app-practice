# ユースケース記述

#### UC-01: {動詞で終わるユースケース名}
- **アクター**: 訪問者
- **事前条件**: なし
- **基本フロー**:
    1. 訪問者が名前・メールアドレス・パスワードを入力して登録ボタンを押す。
    2. システムが登録完了後、/postに画面遷移する。

- **代替フロー**:
    - 1a. 名前・メールアドレス・パスワードに誤りがある場合：エラーメッセージを表示しユーザー登録しない。
- **事後条件**: ユーザーが登録され、ログインされる。
- **受け入れ条件**:
    - [ ]  ユーザー登録画面に、名前・メールアドレス・パスワードの入力欄が表示される。
    - [ ]  ユーザー登録画面に、登録ボタンが表示される。
    - [ ]  ユーザー登録後に、/postに遷移する。

## 参考
#### UC-05: 投稿を編集する

- **アクター**: ログイン済み利用者
- **事前条件**: ログインしている。編集する投稿が自分の投稿である
- **基本フロー**:
  1. ログイン済み利用者が投稿一覧画面で、自分の投稿の「編集」を押す
  2. システムが投稿編集画面に、いまのタイトル・カテゴリ・本文を入れて表示する
  3. ログイン済み利用者が内容を書き換えて「更新」を押す
  4. システムが投稿を書き換え、投稿一覧画面へ戻す
- **代替フロー**:
  - 1a. 他人の投稿の編集画面のURLを直接開いた場合：システムは編集画面を表示せず、権限が無いことを伝える
  - 3a. タイトルまたは本文が空の場合：システムはエラーメッセージを表示し、投稿を書き換えない
- **事後条件**: 投稿の内容が書き換わり、投稿一覧画面に反映される
- **受け入れ条件**:
  - [ ] 投稿一覧画面で、自分の投稿にだけ「編集」が表示される
  - [ ] 内容を書き換えて「更新」を押すと、投稿一覧画面に書き換えた内容が表示される
  - [ ] タイトルを空にして「更新」を押すと、エラーメッセージが表示され、投稿の内容は変わらない
